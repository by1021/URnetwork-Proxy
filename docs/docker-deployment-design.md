# Docker 部署设计

日期：2026-11-07。Feature（部署能力）；仓库未初始化 `.ai_state`，沿用直接工作约定。

## 需求与范围

用户要求为当前项目增加 Docker 部署方案。交付可本地构建的镜像、Compose 配置、持久化与部署文档；保留 Python / Shell / Systemd 启动方式。镜像发布、云主机部署和上游代理账号申请不在本次范围。

## 实现选择

- Python slim 镜像，安装 CA 证书与 OpenSSL；应用以 UID/GID 10001 运行。
- 管理端口固定为容器内 8777，网关端口默认映射 10801–10810；宿主机默认发布至全接口（0.0.0.0 / ::），支持外网直连，并支持通过环境变量按需限制为回环地址。
- 命名卷挂载整个 `/data`，配置位于 `/data/config.json`，运行状态位于 `/data/state`。镜像预置无凭据配置模板，首次创建命名卷时初始化；已有卷不覆盖。
- 新增 `URNETWORK_CONFIG_FILE` 环境变量；未设置或为空时仍使用项目根目录 `config.json`。配置保存采用原有原子替换，避免单文件绑定挂载导致保存失败。
- 复用 `/api/health`，探针不依赖登录、上游 API 或代理环境变量；适配管理 Host 白名单。
- 使用 `SIGINT` 触发现有关闭逻辑，Compose 提供停止宽限时间；不另建进程管理器。

## 验收

- AC1: 镜像构建成功，Compose 启动后健康检查通过，管理页面和账号登录可用，不需要上游凭据。
- AC2: 配置路径覆盖、默认路径兼容及配置原子保存有回归测试；控制台修改的配置和管理密码在容器重建后保留。
- AC3: 网关配置、代理认证和 TLS 证书保存在数据卷，重建容器后内容保持；不接触真实上游账号。
- AC4: 默认发布端口绑定宿主机全接口（外网可达），支持环境变量配置绑定地址；容器非 root 运行，本地配置、状态和仓库元数据不进入构建上下文。
- AC5: 正常停止返回退出码 0；文档覆盖首次启动、端口与监听、持久化、迁移、备份恢复、更新及 CLI 使用。
