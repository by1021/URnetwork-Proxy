# 网关代理池与精确位置选择

status: final
date: 2026-11-08

## 背景与目标

用户反馈：ur.io 上游失效后，本地网关持续报上游检测失败，等待新代理生成期间存在真空期。用户已确认实施方案：每个网关端口默认对应三个 ur.io 代理，并支持国家、地区和城市选择。

## 范围

- 固定一个监听端口，默认一主两热备；保留端口、协议及本地代理凭据。
- 已验证备用在上游故障时优先接管；补池和清理不阻塞数据面。
- 节点级健康反馈、有限建连重试、健康连接定向回收、池状态展示。
- 账户级创建限速、资源所有权、停止/删除/配置修改/重启兼容。
- 国家/地区/城市按官方 location_id 精确绑定，主备使用同一约束。
- 修复 API Key 账户能力判断及 unique-exit 的默认恢复策略。

## 不做

- 不迁移已建立 TCP 流，不重放已经发送的业务请求。
- 不改变客户端代理协议，不新增 UDP/BIND 或业务目标直连回退。
- 不自动扩大用户指定的城市/地区，不以任意同名位置代替精确 ID。
- 不申请真实账户代理、清理真实资源、重启现有服务或发布部署；验证使用隔离本地服务和公开只读位置接口。

## 用户视角验收

- 默认三条线路，第一条就绪即可服务；缺额、补充中和全失效明确展示。
- 主用失效且备用就绪时不等待新代理创建；健康连接不因其他节点换线全部断开。
- 原有网关继续使用原端口和凭据，池大小可以调整到 1 以保留单线路行为。
- 用户精确选中的城市/地区在初次创建、补池及换线后不变。
- 配额不足/供给不足有明确提示、有限重试，已有健康线路继续可用。
- 停用、删除和重启不遗漏本工具资源，不删除其他工具创建的代理。

## 取舍与结论

- 默认主用粘性，不逐请求轮询出口；目标是可用性而非无谓改变 IP。
- 位置信息以官方 ID 为绑定依据；第三方 IP 城市/地区数据仅作为实测展示，不用名称相等代替官方位置校验。
- 池计数指通过检测的 UR 代理资源（不同 client_id），不是不同出口 IP 数。指定范围不足三个就绪资源时显示实际可用条数，不悄悄放宽范围；三条资源可能共享实测 IP，不据此宣称三个独立出口。Pro unique-exit 按官方供给分散出口。
- 需求已由用户“开始优化修改”确认，无待澄清问题。
