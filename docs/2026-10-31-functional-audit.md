# 项目功能与可用性检测报告

检测日期：2026-10-31 UTC；截图日期为手机本地时间 2026-11-01。范围：当前工作区代码、正在运行的管理服务、一个既有网关，以及临时测试环境中的生命周期/异常路径。本轮不修改业务源码和配置，不重启用户服务，不创建、删除、换线或清空真实云端代理。

## 结论

**本地代理数据通路可用；远程管理可达性尚未闭环，远程代理直连目前不成立。**

1. 用户截图是浏览器 `ERR_CONNECTION_RESET`，发生在页面加载阶段。它不是网页内部 API 报错，更不是复制地址文案问题；修改 JS 版本或清缓存并未证明可以解决此故障。
2. 当前管理端口 8777 监听全接口；服务端浏览器访问 IP 和域名均正常。但访问本机外部地址的路由实际是 `dev lo`，这些测试不经过手机到服务器的外部链路。
3. 网关端口 1080 实际只绑定 `127.0.0.1`。回环连接成功，本机访问自身网卡 IP 或域名的 1080 均连接拒绝。复制文本改成访问域名不会改变监听范围。
4. 现有一个真实网关的 HTTP 普通转发、HTTP CONNECT + TLS、SOCKS5 + 远端 DNS + TLS 都成功；国家和账号查询正常。
5. 常规回归全部通过，但额外故障注入复现了保存失败显示成功、部分清理显示成功、流量失败回调未接通等缺口。
6. 管理服务当前仍使用默认账号/密码、明文 HTTP、全接口监听；不应直接视作可公开部署的管理服务。

前几轮“复制地址修复”解决的是展示和剪贴板，不是“远程代理端口可用”。两者必须分开验收。

## 截图中的连接重置

### 已确认

- 截图显示 `ERR_CONNECTION_RESET`；页面和管理登录尚未加载。
- 当前进程监听 8777 全接口，IPv4/IPv6 回环及本机网卡地址请求正常；当前 Host 白名单为空，没有因只允许域名而拒绝 IP。
- 本机 IPv4/IPv6 INPUT 策略为 ACCEPT；未见针对 8777 的本机拒绝规则。这不代表云端防火墙、返回路径和客户端代理已经验证。
- 8777 是 HTTP 服务，不提供 TLS；HTTPS 访问同端口会失败。但截图没有足够证据说明浏览器切换了 HTTPS，不能据此归因。
- 域名对应的 Nginx 80 站点根路径返回 404，当前没有为管理 UI 配好的该站点 HTTPS 反代入口。
- 在外网卡上做了 90 秒、只采集 8777 的 SYN/FIN/RST 标志观察，未捕获可关联到手机重试的连接（0 packets captured）。未收到与采样窗口对应的手机重试时间，因此不将此作为运营商/客户端问题的证明。
- 管理 HTTP 实现的 64 个连接配额耗尽时，会直接关闭新连接而不发送 HTTP 错误；临时服务中复现 `RemoteDisconnected`。这是服务端也可能产生连接层失败的路径，不证明截图就是这个原因。

### 定位方案

在手机再次失败的同一时间，关联入口日志和服务端连接标志：

| 观察 | 下一步定位 |
| --- | --- |
| 服务端没有收到 SYN | 核查手机代理/VPN、路由、云端入站规则；先确认捕获网卡、IP 与时间正确 |
| 收到 SYN 并回 SYN-ACK，但没有后续 ACK | 核查返回路径、网络设备和客户端 |
| TCP 已建立，服务端立即关闭/重置 | 查连接配额、进程重启、服务端错误/内核行为 |
| 收到 HTTP GET 且已返回 200，但手机仍重置 | 对照双端抓包检查中间链路/客户端代理 |
| 实际流量为 TLS，但端口是 HTTP | 修正访问协议，或配置正式 TLS 入口 |

只依靠服务器 curl 自己的 IP，不具备定位这类跨网问题的充分证据。使用手机 Wi-Fi、移动网络各一次独立验证，并记录完整 URL、时间与错误码。

## 发现项与修复建议

### P0：管理入口部署安全尚未完成

**事实：** 当前全接口监听，仍可用默认管理凭据登录，HTTP 传输；进程由 root 的交互式 shell 启动。会话 Cookie 具有 HttpOnly/SameSite，但未设置 Secure（`core/web_server.py:520-533`）。

**影响：** 一旦远端能到达端口，默认凭据与明文登录使管理权限保护不足。不能用“手机连不上”推断服务没有对其他网络暴露。

**方案：** 先更换管理密码；部署有效证书的 HTTPS 反向代理，内部管理端口仅允许回环/可信来源；外部 Host 白名单；仅在明确可信的 HTTPS 入口使用 Secure Cookie。反向代理信任规则应显式配置，不能无条件信任任意转发头。使用专用低权限服务账号。

配置文件当前为 0644，但 `/root` 为 0700，不能将其描述为当前已被其他本地用户读取。迁移到共享路径/服务账号前仍应将秘密配置权限固化为 0600。

### P1：远程复制地址与实际监听不匹配

**证据：** `ss` 显示 1080 只绑定回环；回环成功、网卡 IP/域名 1080 连接拒绝；`core/gateway.py:87-94` 拒绝非回环 host，前端 `web/app.js:599-600` 同样只允许回环。

**影响：** 远程用户复制当前访问域名后仍连不上。域名解析成功不等于该域名的代理端口已开放。

**方案：** 将 `listen_host` 与客户端使用的 `advertise_host/advertise_port` 分离。保留默认仅本机模式，新增显式远程模式，配套本地代理认证、可信来源/防火墙规则、IPv4/IPv6 实际监听能力。远程模式的持久化需确保重启仍保留鉴权，不能自动降级免密。HTTPS 反代仅解决管理页，不自动转发 SOCKS/HTTP 代理端口；普通 HTTP 反代/CDN 也不等于通用 TCP 转发。

**验收：** 从第二台设备，使用页面复制的地址，HTTP CONNECT 与 SOCKS5 均成功；错误/缺失凭据被拒绝；重启后仍正常。不能再只检查地址字符串。

### P1：修改网关失败却提示“已保存”

**复现：** 临时网关运行中，将端口改为另一监听器占用的端口；后端返回 HTTP 200、旧端口及 `last_error=local_bind_failed`，前端关闭编辑弹框并提示“网关设置已保存”。

**位置：** `core/gateway.py:638-646`、`core/web_server.py:535`、`web/app.js:627-631`。

**方案：** 操作响应区分 `applied`、`pending`、`failed`；失败返回明确错误码/状态，前端保留草稿并展示实际结果；保存成功需核对返回配置。候选节点失败、启动失败和长操作也使用同一结果模型，不能将 HTTP 200 当成业务成功。

**验收：** 端口占用时旧网关继续可用、UI 不提示成功、输入不丢；释放端口后再次保存成功。

### P1：清理部分失败仍返回成功，且与活跃网关恢复有冲突

**复现：** 仅在模拟客户端中，一项删除成功、一项删除失败、客户端重置失败；最终仍返回 `ok=true`、删除数 1。前端可显示“清理成功”，没有失败清单。真实全量清理未执行。

**位置：** `core/client.py:301-328`、`core/web_server.py:204-218`、`web/app.js:934-943`。

**补充：** 全量清理没有暂停管理器的活跃网关；UI 已提示网关会重新分配，因此“全部清空”不保证是持续状态。它还可能影响非本工具创建的代理。

**方案：** 返回总数、成功、失败、失败原因及重置状态；部分失败明确告警。区分“回收本工具资源”与“全账号重置”；全账号动作须列影响、互斥进行，并明确暂停/恢复策略。重试只处理失败项。

### P2：流量失败触发提前检测的回调未接通

**证据：** `MixedProxyServer` 接受并保存 `on_result`，但没有调用。临时请求在缺少上游时返回 502，回调列表仍为空。管理器 `_on_result` 原本负责将下次检查提前（`core/gateway.py:576-579`）。

**影响：** 定时自愈可工作，但实际流量失败不会触发设计中的提前检测。测试通过证明的是周期检查，而不是流量反馈路径完整。

**方案：** 对上游握手/网络失败接通回调；不要将客户端主动断开、网站业务错误或鉴权失败直接当成上游坏掉。仍须完整健康探测后再投票换线。

### P1/P2：服务常驻与可观测性不足

- 当前不是已安装的 systemd 服务；模板 `WorkingDirectory` 和 `User` 被注释，`main.py` 为相对路径，不能作为开箱可用 unit。
- 后端关闭 HTTP 访问日志，缺少请求 ID、关闭原因、活跃连接数和拒绝计数；保护秘密不意味着必须完全没有诊断日志。
- 运行时 backlog 为 5，管理连接上限 64，饱和直接关闭。未做真实服务压力测试，因此不声明当前负载导致截图错误。
- `/api/health` 只说明 HTTP 进程可响应，不说明网关、上游、监听和外部路由全部正常。

**方案：** 完整 service 配置，固定工作目录/解释器、非 root、启动恢复和优雅停止；加限量脱敏结构化日志、连接拒绝计数和明确过载响应；区分 liveness、readiness 与各网关数据面状态。按负载实测调整队列/超时，而不是盲目扩大连接数。

### P2：出口 IP 的展示和测试含义需要收窄

**实测：** 同一个网关对两个 IP 查询站点、HTTP/HTTPS 目标返回了不同出口值；请求均成功。这不一定是网关 bug，但“出口 IP”单个字段不代表所有流量都经同一个固定 IP。

**源码：** `core/checker.py:137-153` 检测两个隧道协议，最终只保留一个成功结果；普通 HTTP 转发未独立纳入周期健康探测。

**方案：** 显示“最近探测出口 IP”、探测目标、协议和时间；必要时分别检查 HTTP 普通转发、HTTP CONNECT、SOCKS5。不要承诺跨目标、跨协议的固定出口一致性。

### P2：交付证据和架构说明已出现漂移

旧文档仍写“Web 仅回环”“不调用全账号清空接口”，与当前可全接口监听和全量清理按钮不一致；旧 verification 文件的 Windows 路径、76 测试不是当前 Linux 检测结果。

**方案：** 维护一份当前架构/验证入口，历史记录加日期；CI 增加故障场景和端到端外部验证，不以测试数代替业务验收。

## 建议实施顺序及验收

| 顺序 | 改进切片 | 验收标准 |
| --- | --- | --- |
| 1 | 入口安全与手机连接定位 | 独立强密码、可信 HTTPS 管理入口；手机 Wi-Fi/移动网络各一次真实登录，失败时有对应入口证据；未通过不宣称远程可用 |
| 2 | 远程网关实际可用 | 显式远程模式、认证、监听与广告地址分离；第二台设备粘贴地址即可完成两种代理请求，错误凭据拒绝，重启保持 |
| 3 | 操作结果一致性 | 端口/国家修改失败保留旧网关与表单，不假报成功；清理部分失败可见且可单项重试 |
| 4 | 自愈与运行托管 | 流量失败促发检测但不盲换线；服务优雅停止/恢复；重建不泄漏云端资源 |
| 5 | 可观测性与交付 | 版本、readiness、监听/上游/外部测试分层；记录拒绝原因；同步架构文档和回归矩阵 |

不建议把全部网关直接改成无认证的全接口监听，或只改地址文字后就把“直接使用”标记为完成。
