# 界面卡顿修复设计

日期：2026-11-01。路径：Bugfix；单一验收目标为消除管理界面的重复渲染与后台轮询开销。项目没有 `.ai_state`，不初始化、不伪造 sprint；直接实施并使用 `athena run` 执行检查。

## 当前 / 期望 / 不变行为

- 当前：任一网关快照变化会替换所有卡片；每次事件轮询重建最多 300 行及网关筛选项，即使没有新事件；不可见页面仍执行周期请求；国家搜索反复排序、地区名称转换；数字及日期格式化反复构造格式器。
- 期望：按网关 ID 复用未变化卡片；事件、筛选项、国家列表按实际变化更新；隐藏视图延迟构建；后台暂停周期请求、回前台补同步；搜索按帧合并；复用国际化格式器。
- 不变：5 秒前台网关/事件同步、60 秒账户/健康、5 分钟地区同步；手动刷新、登录/注销、配置草稿保护、网关 CRUD、认证地址复制、移动布局、主题与中文格式不变。不修改后端协议、运行配置、凭据或重启正在运行的服务。
- 选择依据：源码直接显示全量 `replaceChildren`、无条件事件渲染和无可见性约束定时器；先做有界前端修复，而非未经测量重写后端或引入框架。

## 验收

- AC1: 100 个网关中只修改一个时，其余 99 张卡片保持节点身份及焦点；新增、删除、筛选、重排和操作按钮仍反映最新快照。
- AC2: 300 条事件下，无新增事件的刷新不改日志节点/筛选项；新事件、改名、删除及级别筛选正确；不在日志/地区页时不构建隐藏长列表。
- AC3: 标签页隐藏期间不新发周期请求；恢复可见立即同步网关/事件，并刷新到期账户/地区；慢请求去重、退出清理仍有效，不中止后台网关操作。
- AC4: 国家/网关搜索和排序正确；同一帧连续输入只提交最后一次结果；编辑中的国家选择、配置草稿、复制地址不丢失。
- AC5: 同一 Chromium、同一离线负载测量修复前后渲染+布局耗时；单网关刷新中位数降低至少 50%；现有 Python 测试与三个浏览器回归通过；语法、差异检查及独立只读审查通过。

## 验证约束

性能脚本仅使用临时 ManagementServer、离线 API 样本与测试注入观测接口。性能计时记录样本、中位数，不把本机数据等同于所有设备。保护任务开始时已有未提交改动。浏览器截图输出临时目录，不覆盖已有界面证据。

## API 依据

- MDN `Number.prototype.toLocaleString`：重复格式化使用复用的 `Intl.NumberFormat`。
- MDN `Page Visibility API`：根据 `document.hidden` 与 `visibilitychange` 管理后台工作；不依赖浏览器自动定时器节流。
- 源码依据：`web/app.js` 的 `startPolling`、`renderGateways`、`loadEvents`、`renderCountries`。
