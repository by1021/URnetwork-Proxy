## 背景与实现边界

现有 Web 位置查询需要手动输入词；地区记录已有国家、类型、provider_count 和 location_id。2026-11-08 公开接口验证国家名查询可返回下级地区。复用现有 GET `/api/locations`、目录缓存和服务端位置验证，改前端交互，不改变代理创建与网关模型。

仓库没有 `.ai_state`，按项目约定直接工作，不擅自初始化；`athena run` 不会记录原生 sprint 门禁证据。保留本轮前快照、红／绿测试和独立只读审查，不冒充原生 Athena PASS/current。现有未提交改动保留，仅审查本轮增量。

## 验收标准

- AC1: 地区模式隐藏查询输入／搜索按钮，未选国家不请求；选国家或切换到地区模式后自动加载列表，提供刷新地区按钮。
- AC2: 查询使用官方国家名称（既有暂不可用绑定用国家英文名称），地区结果按国家、region 类型和 provider_count > 0 筛选；绑定仍使用原始 location_id。
- AC3: 切换国家（包括国家搜索导致选择消失）、模式或关闭／重开表单时清空或隔离旧结果；迟到请求不会覆盖新列表或错误改变按钮状态。
- AC4: 加载、失败、无供给和过期快照有针对地区的提示；过期结果不用于新绑定；刷新可恢复，无自动全国回退。
- AC5: 编辑地区网关自动加载目录并保留已绑定位置；位置暂缺／刷新失败时未改动绑定仍可编辑无关字段，其他地区须刷新后选择。
- AC6: 国家模式与城市搜索不变；组件及生产管理器集成测试验证地区绑定与三个主备的 wire location_id 不变，全量单测和既有 UI 回归通过。

## 实现与检查

地区和城市共用现有异步位置请求及 request 序号，地区自动生成查询词并过滤供给；地区独立提示／刷新控件，城市保留搜索。表单显示后再发起自动请求，复用既有过期与保存校验。

检查：新地区联动浏览器测试先红后绿；代理池 UI（组件／生产管理器）、既有网关与登录 UI、全量单测、JS 语法和增量 diff 检查；证据见 `.local/region-cascade/`。
